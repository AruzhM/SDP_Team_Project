# Decorator: реализация и подготовка к защите

Основа: ветка `main` репозитория `AruzhM/SDP_Team_Project`, коммит `0a71025f495645c1b3171448b2f389ef9510d3e1`. Проверка: 15 ноября 2026 года.

## Что было и что изменилось

В исходной ветке уже были `Ability`, `BasicAbility`, `AbilityDecorator` и `CrystalAbility`. Они описывали характеристики импульса и награды за квесты, но `GameFacade`, `Main` и `RoomRenderer` их не использовали. Поэтому наличие этих классов не давало демонстрационного сценария работающего паттерна.

В этой доработке добавлены три конкретных декоратора, модель тренировки, обработка импульса в фасаде, мишень в коридоре, панель характеристик и сравнение с базовой способностью. Используется существующий сюжет и события квестов. Подбор кристалла по-прежнему выполняет существующая командная реализация.

## Как запустить

Нужны **JDK 21** и **Maven 3.9+**. В корне проекта:

```bash
mvn clean test
mvn javafx:run
```

Полная проверка, включая JavaFX без экрана:

```bash
mvn -Pheadless-tests clean test
```

Существующий профиль `headless-tests` использует Monocle. Первый запуск Maven требует интернета для зависимостей. Обычный `mvn test` выполняет бизнес-тесты и пропускает GUI-тесты; профиль включает их. В `pom.xml` устранено противоречие между `release=21` и `source/target=25`.

## Демонстрация за 3–4 минуты

1. Создай персонажа. Покажи панель `CRYSTAL TRAINING`: базовые значения **10 / 36 / 0.80**.
2. Подойди к письменному столу и нажми **E**. Завершается первый квест, перезарядка становится **0.52 s**: добавляется `SwiftnessAbility`.
3. Подойди к кристаллу на столике слева и нажми **E**. После существующего перехода в параллельный мир урон становится **20**: добавляется `PowerAbility`.
4. Поговори с Хикари, выбери любой вариант. Радиус становится **52 px**: добавляется `ReachAbility`.
5. Войди в коридор через дверь. Золотая круглая мишень находится справа. Подойди к ней: текущая дистанция показана в панели. Нажимай **Q** или кнопку `Pulse`. Мишень с **60 HP** разрушается за **три** попадания по 20.
6. Нажми **R** или `Reset target`. Включи `Basic pulse (compare)`, дождись перезарядки. Теперь мишени требуется **шесть** попаданий по 10. Сними галочку, чтобы вернуть заработанные улучшения.
7. Для проверки дальности отойди так, чтобы дистанция была **между 36 и 52**. Базовый импульс промахнётся, улучшенный попадёт. Промах тоже запускает перезарядку.
8. Нажми **F5**, затем **F9** несколько раз. Значения остаются **20 / 52 / 0.52**. Улучшения не накладываются повторно. Новая игра возвращает **10 / 36 / 0.80**.

Движение: **WASD**. Взаимодействие: **E**. Пауза: **Esc**. Во время паузы нельзя атаковать, а отсчёт перезарядки заморожен. В сюжетном выборе и активном диалоге тренировочные кнопки отключены.

Радиус и дистанция измеряются в логических пикселях комнаты, а не экранных: рендерер масштабирует комнату в три раза.

## Участники паттерна

| Роль в Decorator | Класс | Ответственность |
|---|---|---|
| Component | `Ability` | Общий контракт имени, урона, дальности и перезарядки |
| Concrete Component | `BasicAbility` | Базовый импульс: 10, 36, 0.8 |
| Base Decorator | `AbilityDecorator` | Хранит `Ability wrapped`, реализует тот же интерфейс и делегирует вызовы |
| Concrete Decorator | `PowerAbility` | Добавляет 10 к урону обёрнутой способности |
| Concrete Decorator | `ReachAbility` | Добавляет 16 к радиусу обёрнутой способности |
| Concrete Decorator | `SwiftnessAbility` | Умножает перезарядку обёрнутой способности на 0.65 |
| Client | `PulseTraining` | Применяет характеристики через интерфейс `Ability` |
| Интеграция | `GameFacade`, `Main`, `RoomRenderer` | Квесты, ввод, игровой результат и визуализация |
| Построение цепочки | `CrystalAbility.fromQuests()` | Выбирает декораторы по завершённым квестам |

`CrystalAbility(Ability, Upgrade)` сохранён как совместимый вход старого API. Он делегирует новым конкретным классам. В новой игровой цепочке используются `PowerAbility`, `SwiftnessAbility` и `ReachAbility`, а не ветвления по enum при каждом вычислении характеристики.

## Главная идея на коде

```java
Ability ability = new BasicAbility();
ability = new PowerAbility(ability);
ability = new SwiftnessAbility(ability);
ability = new ReachAbility(ability);

// Эквивалентная вложенная запись:
Ability same = new ReachAbility(
        new SwiftnessAbility(new PowerAbility(new BasicAbility())));
```

Здесь создаются **объекты-обёртки**. Это не Java-аннотации и не декоративный графический эффект. Внешний объект имеет тот же интерфейс, что и исходный.

Например, вызов `getDamage()` проходит через `ReachAbility` и `SwiftnessAbility` без изменений, затем `PowerAbility` получает 10 от `BasicAbility` и добавляет 10. Итог: 20. `PulseTraining` не проверяет `instanceof PowerAbility` и не знает, сколько обёрток в цепочке.

```java
public final class PowerAbility extends AbilityDecorator {
    public PowerAbility(Ability wrapped) { super(wrapped); }

    @Override public int getDamage() {
        return super.getDamage() + 10;
    }
}
```

`super.getDamage()` вызывает метод базового декоратора, который обращается к `wrapped.getDamage()`. Остальные методы наследуются и продолжают делегировать.

## Почему Decorator подходит

Без композиции пришлось бы создавать отдельные классы для сочетаний: обычный импульс, сильный, дальний, быстрый, сильный-дальний, сильный-быстрый и т.д. Для трёх независимо включаемых улучшений уже существует восемь комбинаций. Декораторы позволяют собрать нужное сочетание во время выполнения.

**SRP:** каждый конкретный декоратор отвечает за одно улучшение, `PulseTraining` — за попадания и перезарядку, рендерер — за изображение.

**OCP:** новый модификатор можно добавить отдельным классом, не меняя `BasicAbility` и алгоритм `PulseTraining`. При этом подключить новую награду в `fromQuests()` всё равно потребуется: принцип не означает, что никакой файл никогда не меняется.

**DIP:** бизнес-логика тренировки принимает `Ability`, а не конкретный класс улучшения.

**LSP:** обёртки используются там, где ожидается `Ability`; они сохраняют смысл характеристик. Некорректные отрицательные или нечисловые значения от будущих декораторов отклоняются моделью тренировки до изменения здоровья.

## Связь с другими частями проекта

`GameEventPublisher` отправляет событие действия. Существующий `QuestManager` завершает соответствующий квест и публикует `QUEST_COMPLETED`. Подписка в `GameFacade` собирает новую цепочку через `CrystalAbility.fromQuests(quests)`. UI читает её через `getAbility()`.

Нажатие Q вызывает `GameFacade.usePulse()`. Фасад проверяет состояние игры и дистанцию, затем передаёт текущую `Ability` в `PulseTraining.fire()`. Модель возвращает результат, а фасад обновляет здоровье мишени и запускает визуальный импульс. Поэтому значения из декораторов действительно влияют на действие пользователя.

## Сохранения и ограничения

Сохраняются завершённые квесты в существующем `save.properties` версии 3. При загрузке цепочка строится заново от `BasicAbility`; в каждой сборке каждый заработанный модификатор добавляется один раз. Формат сохранений не изменён.

Мишень — **временная тренировка**. Её здоровье, текущая перезарядка и режим сравнения не сохраняются: новая игра или загрузка начинает тренировку с 60 HP и возвращает заработанные улучшения. Сброс мишени клавишей R и переключение базового режима **не сбрасывают текущую перезарядку**. Изменившееся значение cooldown применяется к следующему импульсу.

В базовой истории нет врагов; добавлена отдельная тренировочная мишень, без новой обязательной сюжетной развилки. В текущем варианте импульс действует по круговому радиусу, не проверяет направление взгляда и препятствия. Это учебная механика, а не полноценная боевая система.

Декораторы сами допускают повторное оборачивание: `Power(Power(Basic))` даст 30 урона. Ограничение «одна награда за квест» обеспечивает место сборки цепочки, а не паттерн сам по себе. У будущих модификаторов порядок может влиять на результат, например при сочетании прибавления и умножения урона. Для текущих трёх независимых характеристик итоговые числа от порядка не зависят.

## Что сказать на защите

Краткое объяснение своими словами:

«Я использую Decorator для улучшений способности персонажа. `Ability` — общий интерфейс, `BasicAbility` — базовая реализация. `AbilityDecorator` содержит ссылку на другую `Ability`. Конкретные декораторы добавляют урон, радиус или уменьшают перезарядку. После выполнения квестов игра собирает цепочку обёрток. Тренировочная мишень использует только интерфейс, поэтому новая комбинация работает без изменения логики попаданий. Я могу показать разницу в GUI и проверить её тестами».

### Типичные вопросы

| Вопрос | Ответ |
|---|---|
| Это наследование или композиция? | Оба механизма присутствуют, но комбинации возможностей строятся композицией объектов через `wrapped`. |
| Чем отличается от Strategy? | Strategy заменяет алгоритм операции. Decorator последовательно добавляет поведение к объекту с тем же интерфейсом. |
| Чем отличается от Adapter? | Adapter приводит несовместимый интерфейс к ожидаемому. Здесь интерфейс остаётся `Ability`. |
| Чем отличается от Builder? | Builder собирает объект. Decorator создаёт обёртку, которая продолжает участвовать в каждом вызове. |
| Почему не просто поля damage/range? | Для трёх чисел поля проще; паттерн оправдан, когда нужны самостоятельные комбинируемые модификаторы. Минусы здесь — дополнительные классы и цепочка делегирования. |
| Зачем общий интерфейс у обёртки и компонента? | Тогда любую обёртку можно передать клиенту или обернуть ещё одним декоратором. |
| Как убрать бонус? | Пересобрать цепочку без нужной обёртки. Режим сравнения в игре подставляет `BasicAbility`. |
| Сколько стоит вычисление? | O(k) по числу обёрток; построение и хранение цепочки также O(k). Здесь k не больше трёх в обычной игре. |

### Упражнение для изменения вживую

Самостоятельно добавь `FocusAbility extends AbilityDecorator`, который увеличивает урон на 5. Переопредели `getDamage()` и `getName()`, подключи обёртку после завершённого `CROSS_BOUNDARY` в `fromQuests()`. Ожидаемый урон полностью улучшенного импульса станет 25. Обнови тесты новой награды и покажи результат в панели. `PulseTraining` менять не потребуется. Этот класс намеренно не реализован в пакете, чтобы можно было потренироваться.
